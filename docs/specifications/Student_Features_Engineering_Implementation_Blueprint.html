Part 1: The First-Login Onboarding & AI Certificate Verification Engine Onboarding Core
The 5-Step First-Login Onboarding & Verification Lifecycle:
1 Initial Login Student signs in via college credentials/OAuth. System detects is_onboarded: false.
2 Immediate Resume Ingestion Prompts drag-and-drop resume upload (PDF). Local server parses text in <100ms with DPDP PII masking.
3 AI Profile Synthesis Server AI synthesizes profile: extracts skills, education, GitHub repos, and initial proficiency levels.
4 Review & Verification Modal Student reviews profile: adds missing achievements, projects, and uploads certificates for AI credibility check.
5 Landing Page Launch Student is redirected to Dashboard with populated match rings, verified badges, and personalized opportunities!
Feature 1: First-Login Resume Ingestion & Profile Synthesis Wizard Onboarding Wizard • Route: /student/onboarding
Objective & User Flow
Immediately upon first login, new students are greeted with a clean 3-step modal wizard. Instead of filling tedious forms, the student uploads their existing PDF resume. The server extracts the text, sends a sanitized prompt to Gemini 2.5 Flash, and returns a structured profile JSON. The student verifies details and proceeds.
Developer Implementation Details
  • Trigger: In AuthContext.jsx, check user.onboarded. If false, route to /student/onboarding.
  • Backend Controller: POST /api/student/onboard/parse-resume parses PDF using pypdf, runs the DPDP PII scrubber, and calls Gemini with strict Pydantic schema validation.
  • Zero-Crash Safety: If PDF parsing fails (e.g. image-only PDF), the wizard gracefully provides a pre-filled manual fallback form without throwing errors.
Feature 2: Dedicated AI Certificate Credibility & Anti-Forgery Verification Engine 3-Layer Verification Pipeline
The Three-Layer Credibility Pipeline (How It Detects Forgeries)
  1. Layer 1: Multimodal Vision AI (Gemini 2.5 Flash Vision / LayoutLMv3): Inspects layout, official issuing typography, recognized logo vectors, standardized course codes, and authorized digital signatures (NPTEL, Coursera, AWS, edX, IITs). Flags distorted seals or template mismatches.
  2. Layer 2: PDF XMP Metadata & Splicing Anomaly Detection (Python pikepdf & OpenCV): Inspects binary metadata to flag documents modified by editing software (Photoshop, Canva, Illustrator), detects mismatched font layers (where a student edits the name over someone else's certificate), and catches altered date strings.
  3. Layer 3: Automated QR Code & Registry Webhook Resolver (Python pyzbar): Decodes embedded QR codes or verification URLs (e.g., nptel.ac.in/noc/Ecertificate) and queries the issuing academy's public API to confirm matching student names and completion grades.
Confidence Tiers & TrustLedger Action
Confidence Assigned Status System Action
≥ 90% VERIFIED Displays green verified badge on portfolio; mints SHA-256 certificate block to TrustLedger.
70% – 89% PENDING_AUDIT Saved as self-claim until secondary automated registry webhook confirmation.
< 70% / Tampered REJECTED / FORGED Rejected with detailed alert: "Document failed metadata integrity check (Font layer splice detected)."

  • Backend: POST /api/assessments/submit calculates score, verifies integrity violations, and mints an NSQF Certified Badge (Gold/Silver/Bronze) with an immutable SHA-256 block hash.
